# KEGG MCP

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

**Codex に依頼して、タンパク質 FASTA または KO エビデンスを、追跡可能な KEGG
レポートとオプションのグラフィックスへローカルで変換します。**

KEGG MCP は、研究者が自然言語で依頼することにより、タンパク質配列のアノテーション、
既存の KEGG Orthology（KO）エビデンスの確認、選択した KEGG リファレンスの探索を
行えるよう支援します。エビデンス、判断、来歴、生成ファイルをまとめて保持するため、
結果をブラックボックスとして扱わず、後から検証できます。

MCP は Model Context Protocol の略で、このスイートのツールを Codex から呼び出すための
ローカルインターフェースです。KEGG MCP はウェブサイトでもホスト型解析サービスでも
ありません。

> [!IMPORTANT]
> **プロジェクトの状態：** Alpha。完全なスイートは Linux と Apple Silicon 搭載 Mac 上の
> ネイティブ macOS 14 以降を対象とし、Python 3.11.x が必要です。Windows ユーザーは
> WSL2 を使用してください。ネイティブ Windows と Intel macOS はサポートされていません。
> 統合インストールは引き続きリリースゲートの対象であるため、レビュー済みリリースを
> チェックアウトし、[インストールガイド](docs/installation.md)に従ってください。

> [!NOTE]
> 結果が示すのは、アノテーションエビデンスと KEGG リファレンス上の関係です。実験的機能、
> パスウェイの存在または活性、フラックス、表現型、統計的エンリッチメントを証明するものでは
> ありません。

## 何ができますか？

すでに手元にある資料から始められます。

| 手元にあるもの | KEGG MCP でできること | 得られるもの |
| --- | --- | --- |
| タンパク質 FASTA | 設定済みのローカル DeepKOALA アノテーションを実行して KO エビデンスを生成し、その後解析する | アノテーションエビデンス、読みやすい解析レポート、確認可能な表、オプションのグラフィックス |
| K-number のリストまたはアノテーション表 | 配列アノテーションを省略し、MODULE 評価、記述的なパスウェイ KO カバレッジ、または KO セット比較へ直接進む | レポートと、追跡可能な CSV、TSV、JSON 形式の結果 |
| KEGG 用語またはサポート対象の識別子 | 候補を検索し、選択したエントリを確認し、一致項目を暗黙に選ばず曖昧性を保持する | 取得の詳細を伴う、限定的で追跡可能なクエリ結果 |

頻度の低いワークフローでは、KEGG に明示的に記載された PubMed 識別子の取得、明示的な
関係タイプによる KEGG 関係の追跡、選択したリファレンスの保持、サポート対象の KEGG Mapper
または KEGG Syntax ルート向けに検証済みローカル入力ファイルを準備することもできます。
全機能の一覧は、[Core MCP リファレンス](docs/mcp-server.md)を参照してください。

## 結果はどのような形式ですか？

1 回の依頼で、次の 3 種類の出力を生成できます。

- **読みやすいレポート**：解析対象を説明し、主要な結果を要約します。
- **確認可能なエビデンスファイル**：判断と来歴を含む CSV、TSV、JSON 形式のファイルです。
- **オプションの静的グラフィックス**：選択したパスウェイオーバーレイまたは MODULE ロジックを
  SVG または PNG 形式で出力します。

すべての依頼で全種類の出力が生成されるわけではありません。KO エビデンスがすでにある場合、
オプションの DeepKOALA ステップは省略されます。レンダリングは常に任意です。

## このツールは目的に合っていますか？

### 適している用途

- タンパク質 FASTA、KO 識別子、またはアノテーション表がある。
- 再現可能な KEGG 指向のワークフローを Codex にオーケストレーションさせたい。
- 曖昧性、複数の割り当て、しきい値、来歴を見える状態に保つ必要がある。
- ホスト型のマルチユーザーサービスより、ローカルファイルと明示的なネットワークアクセスを
  使用したい。

### 対象外の用途

- 遺伝子予測、翻訳、配列アラインメント、無制限のゲノムアノテーション。
- 統計的エンリッチメント、差次的アバンダンス、代謝モデリング、フラックス、表現型予測。
- KEGG 以外のデータベース、任意のグラフ探索、因果ネットワーク解析。
- ウェブ UI、一般公開ホスティング、マルチユーザーストレージ、KEGG コンテンツの再配布。

## 試してみる

スイートをインストールし、ローカル設定で許可されたフォルダー内にファイルを配置すれば、
研究タスクに集中したプロンプトを使用できます。

### タンパク質 FASTA

> `/absolute/project/inputs/proteins.faa` を分離株プロテオームとしてアノテーションしてください。
> 生成された KO エビデンスを解析し、選択した MODULE の結果と記述的なパスウェイ KO
> カバレッジを要約し、選択した結果を SVG としてレンダリングしてください。特定された
> DeepKOALA モデルのバージョンも報告してください。

### 既存の KO エビデンス

> `/absolute/project/inputs/mag-ko.tsv` を MAG として解析してください。採用されたエビデンスと
> 不確実なエビデンスを分け、厳密な MODULE 完了度とパスウェイ KO カバレッジを別々に
> 説明してください。

### KEGG 候補検索

> KEGG Orthology で `citrate synthase` を検索してください。最良の一致を選ばずにすべての候補を
> 保持し、私が選択した識別子だけについて詳細を取得してください。

その他の合成例は、[サンプルガイド](examples/README.md)で確認できます。解析単位が分離株ゲノム、
MAG、分離株プロテオーム、パンゲノム、メタゲノムコミュニティのいずれか分かっている場合は、
その情報をスイートに伝えてください。

## はじめに

### Codex または ChatGPT でインストールする

最も簡単な方法は、ローカルファイルとターミナルにアクセスできるアシスタントに、この
リポジトリを指定することです。

1. リポジトリの URL をコピーします。

   ```text
   https://github.com/zhaoxi120/kegg_mcp
   ```

2. Codex、またはローカルターミナルへアクセスできる ChatGPT ワークスペースに URL と次の
   依頼を貼り付けます。

   > このリポジトリから KEGG MCP をインストールしてください。`docs/installation.md` に厳密に
   > 従ってください。レビュー済みリリースのチェックアウトを探し、見つからなければ停止して
   > ください。私のプラットフォームと前提条件がサポート対象か確認してください。変更を加える
   > 前に、必要なプライベートディレクトリ、私の KEGG 利用資格とアクセスモード、DeepKOALA の
   > ダウンロードについて確認を求めてください。まず変更を伴わない事前確認を実行し、成功した
   > 場合のみ続行してください。インストール後は、現在のタスクから再インストールしないで
   > ください。ソースのチェックアウト外で新しい Codex タスクを開始し、リポジトリの 3 つの
   > Skills とそのローカル MCP サーバーを検証する方法を教えてください。

3. ローカルパス、ダウンロード、KEGG アクセスに関するアシスタントの質問に回答します。
   インストールが完了したら、ソースのチェックアウト外で新しい Codex タスクを開き、上記の
   プロンプトのいずれかを試してください。

現在、完全なセットアップには次のものが必要です。

- Linux、または Apple Silicon 搭載 Mac 上のネイティブ macOS 14 以降。Windows ホストでは
  WSL2 を使用します。
- Python 3.11.x、`uv` 0.11.16 以降、Git、ローカルプラグインをサポートする Codex CLI。
- レビュー済みリリースのチェックアウト、プライベートな状態・プロジェクトディレクトリ、
  明示的に指定した 1 つの KEGG アクセスモード。

ターミナルにアクセスできる ChatGPT ワークスペースはセットアップを支援できますが、
インストールした Skills と MCP サーバーは Codex で有効になります。ローカルファイルと
ターミナルにアクセスできない通常のチャットでは、インストール手順の説明のみ可能です。
手動セットアップと運用の詳細は、[インストールと運用](docs/installation.md)を参照してください。

Codex の完全なセットアップには **suite installer** を使用してください。Core と DeepKOALA の
Python wheel は、別のサーバーディストリビューションを依存関係として導入しません。
Renderer の Python wheel は、共有型付きコントラクトと KEGG アセットへのアクセスに必要な
互換性のある Core ディストリビューションを依存関係としてインストールしますが、Core stdio
サーバーを登録または起動することはありません。いずれの wheel も、リポジトリスコープの Skills
をインストールしません。**wheel を単独でインストールしても、リポジトリスコープの Skills は
利用できるようになりません。** コンポーネントごとのセットアップについては、
[手動デプロイ](docs/manual-component-deployment.md)を参照してください。

## 責任を持って結果を解釈する

- K-number の割り当てはアノテーションエビデンスであり、実験的検証ではありません。
- 厳密な KEGG MODULE 完了度は、サポート対象のリファレンスロジックを評価するものです。
  パスウェイ活性、フラックス、表現型を立証するものではありません。
- パスウェイ KO カバレッジは、明示的なリファレンス分母に対する記述的な重なりです。
  パスウェイの存在、完全性、活性、エンリッチメントを示すものではありません。
- 検索結果は候補であり、自動的に確定された同一性ではありません。
- マッピングされなかった識別子やキャッシュミスは、生物学的実体が存在しないことの
  エビデンスではありません。

ソースとポリシーが判断をサポートする場合、レポートでは採用、不確実、棄却、重複、競合する
エビデンスを区別して保持します。コミュニティとパンゲノムの結果は、単一の分離株ではなく、
プール全体にコードされた潜在能力を表します。

## ローカルデータと KEGG アクセス

- 入力ファイルと生成結果は、ローカル設定で許可されたフォルダー内にとどまります。ライブ
  モードで送信されるのは、選択した KEGG リクエストに必要な限定的な識別子、用語、パラメーター
  のみです。
- ユーザーと研究の双方が公開学術向け KEGG REST アクセスの条件を満たす場合に限り、確認済みの
  `public_academic` アクセスを使用してください。それ以外のライブ環境では、適切にライセンス
  されたエンドポイントが必要です。
- `offline_cache` は KEGG HTTP リクエストを発行せず、ネットワークへのフォールバックも
  行いません。
- キャッシュされた KEGG レスポンス、パスウェイアセット、レンダリングされた派生物は、
  ローカルに保持し、バージョン管理、パッケージ、サンプル、CI アーティファクト、リリースに
  含めてはなりません。
- MIT ソースライセンスは、KEGG コンテンツ、DeepKOALA のコードまたは重み、KOfam profiles、
  その他の第三者資料に対する権利を付与するものではありません。

ライブ利用の前に、[KEGG API ドキュメント](https://www.kegg.jp/kegg/rest/)と
[KEGG 法的通知](https://www.kegg.jp/kegg/legal.html)を確認してください。
